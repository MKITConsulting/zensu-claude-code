# Automatic feature context

The prompt hook loads a context package when the main user prompt contains one distinct explicit KEY-N reference. This applies to questions, planning, reviews and direct implementation as well as tracked implementation. A hook call creates an ordinary authenticated retrieval receipt, visible in the existing Context Board. It never starts TDD, a review chain, a sync or a feature mutation.

The hook checks the installed CLI for `--agent` and `--context-load`, then calls `zensu knowledge context-pack <feature-ref> --json --agent claude-code`. Authentication and the configurable SaaS/self-hosted endpoint remain owned by the CLI. For explicit keys only the key and host label are transmitted. Without a key, discovery sends up to 2,000 characters of the current human task prose to the configured Zensu backend after excluding fenced/quoted blocks, URLs and file-path tokens. It never sends session IDs or the chat transcript. The existing knowledge search may use its configured embedding provider; its full-text fallback remains available for self-hosted installations.

The response supplies `load_id`, server time, feature identity and linked context. The agent retains that receipt for the same feature and task, chooses relevant real items, and fetches them with `zensu knowledge get <item-id> --json --context-load <load-id>`. It also uses that ID for relevant search results. The Implement skill reuses a matching automatic package rather than loading a second one. Structural product/component nodes are not fetched as knowledge items.

The hook never guesses a feature from a title or repository; the agent reasons over task candidates. Ambiguous references, quoted blocks, file paths, URLs, harness notifications and child-agent prompts do not trigger a read. Without an explicit key, the hook calls `zensu knowledge context-search --query <task-description> --json` automatically. This requires a CLI exposing `context-search`; an older CLI produces an unavailability notice. Discovery performs one organization-scoped search plus at most five canonical feature-item reads, deduplicates features and returns bounded candidate evidence. The main agent must match the task and the authorized repository/product scope, then automatically load the matching package with `--agent` before substantive work. Retrieval rank is not selection confidence. Unresolved ambiguity requires one focused question; no candidates means an incomplete search, not an invented feature. `--product <UUID>` can refine candidates within the bounded result set. Search/item discovery has no Context Board receipt; the subsequent package and correlated source reads do. Greetings and unrelated requests do not call for a package. This is conservative prompt recognition, not semantic intent detection: a lone unquoted key in prose can trigger a read even if it is only being discussed. Repeated user submissions can create fresh receipts. An existing receipt is never borrowed from another session or inferred from history.

A single eight-second deadline covers capability checks and retrieval. Missing/old CLI capabilities, authentication failures, malformed receipts and timeouts produce a visible unavailability notice without blocking unrelated work. There is no automatic retry or silent untracked fallback. A timeout can occur after the server recorded a receipt. The executable must resolve from an absolute installed PATH directory outside the working repository; relative/repository PATH entries are refused. CLI update checking is disabled for these calls.

The returned source data is explicitly untrusted. Rendering spends its 24 KB JSON budget and 64-node limit on `layers` first, preserving direct/supporting excerpts and their `relevance`, `reason` and directed `path`. The remaining budget carries `related_layers` as a separate metadata-only index, without excerpts or automatic source fetches. The agent must name a specific unresolved task question before choosing a related item; shared sources alone never establish dependencies. `display_counts` records shown versus returned entries per group, not total graph size. `display_truncated` is separate from server graph truncation; `path_truncated` marks an incomplete displayed path. Legacy responses without `related_layers` carry `relevance_separated: false` and require an explicit relevance assessment. Targeted search and correlated item reads recover relevant omitted content. The hook keeps no local cache of source contents or receipts. Local file reads still use the host's file tool and are not reported to the backend. API retrieval does not prove model comprehension or use.

Set `hooks.contextAutoLoad` to `false` in the normal Zensu configuration to disable automatic reads. The existing manual tracked CLI procedure remains available. Host labels are client declarations, not authenticated model or subagent identities.
