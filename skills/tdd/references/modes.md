# Mode-gated deltas

Read this when Phase 0 step 2's `--full-suite-policy` prints `full suite: ci`, or when Phase 0 step 3's `--tdd-begin` echoes `mode: vanilla`. Each section changes only what it names; everything else runs as written in `SKILL.md` and the other references.

## Vanilla Implementation Mode (mode-gated deltas)

Active when Phase 0's `--tdd-begin` echoes `mode: vanilla` — whichever rank won at begin time (the session's `/zensu:tdd-mode` marker, then the caller's `--tdd-mode strict`, then `hooks.tddImplementation`, then the vanilla default), frozen per session into the state file's `vanilla` flag. Re-query any time with `CLAUDE_PLUGIN_DATA="{plugin_data}" bash "{plugin_root}/hooks/lib/zensu-log.sh" --mode` (echoes `strict`/`vanilla`). Everything not listed below runs EXACTLY as written — especially Phase 5 and the whole Phase 6 audit (the full-suite runner, build verification, coverage, the Edit Landing Audit, the Precondition Drift Audit, review fan-out → judge second pass → Finding Verification Gate → consume-mode reviewer → self-review terminus) and the Stop-hook chain guarantee.

- Principles 1-2 (RED→GREEN cycles, work types, cross-layer pairing) and the FSM phase markers do NOT apply; the PreToolUse edit gate passes through.
- Tests are at your discretion — write them where they add value; none is acceptable. The Phase 5/6 suites, build, coverage, and the review chain are the safety net.
- Phase 2 plan: `**Approach**: Vanilla implementation (strict TDD discipline not in effect for this chain)`; omit the per-step RED/GREEN bullets and Cross-Layer rows (keep the heading). The `## Preconditions` table is unchanged and binding. The `## Requirements` table and the per-step `Covers` mapping are likewise unchanged and binding (Phase 6 step 6c runs in vanilla).
- Phase 3: ONE task per step — `{step_id} [impl]` (activeForm: "Implementing {step_id}"); integration `[wire]` unchanged.
- Phase 4 replaced: implement each step directly. The Feature-Cycle precondition self-check still applies — a step referencing a precondition marked `missing` with decision `skip` → mark `[!]`, log `{step_id} BLOCKED — precondition {name} missing`, TaskUpdate `cancelled`, next step. Log `{step_id} IMPL completed — files: {list}`; TaskUpdate `[impl]` completed; plan status `[I]`. Optionally log `{step_id} TESTED — {test_file}` when you wrote a test. The **mechanical-replacement re-read rule** in Phase 4 B) applies unchanged — vanilla removes the RED→GREEN ceremony, never the obligation to verify that an edit landed.
- Phase 6: only the mtime Discipline Audit and the Cross-Layer Value Flow Audit are skipped — log `DISCIPLINE AUDIT SKIPPED — vanilla mode` instead; the Precondition Drift Audit and the Edit Landing Audit still run. The Edit Landing Audit is NEVER skipped in vanilla: with the mtime audit gone it is the only remaining check that a claimed edit produced a real change. Step 7 closure accepts `[I]`/`[W]`/`[!]`. Step 8 final line: `VANILLA COMPLETE — {N}/{M} implemented | Build: {…} | Coverage: {…}`.
- Review-fix rounds and the self-review fix round are vanilla too: fix findings directly (no RED→GREEN cycle), keep logging CHECKPOINT lines and re-running each round's own scoped suites (the full suite runs only where step 10 and `/zensu:self-review` name it), log `{step_id} IMPL completed — files: {list}` for every fix (the per-round Edit Landing Audit has nothing to grade otherwise), re-run the fan-out + step-4c Finding Verification Gate + consume-mode reviewer per round.

## Full Suite in CI (mode-gated deltas)

Active when Phase 0 step 2's `--full-suite-policy` prints `full suite: ci`; `local` leaves every phase as written. The plugin verified that the repository's CI pull-request pipeline runs the suite, so this chain never runs the FULL suite locally: `--evidence-run --scope full` refuses with exit 2, which is NOT a suite failure, and `--local` is only for a local full run the user explicitly asked for. Phase 5: where the fallback would run the full suite, run no extra suite and log `| scope: deferred-ci — {reason}` instead. Phase 6 step 1 runs the AFFECTED suite through the runner instead — the Phase 6 affected-suite command: `--evidence-run --scope scoped --cmd '{scoped_test_cmd} <every suite Phase 5 would pick for the whole change>' --log {log_file}`; when no suite covers the change, run the smallest suite that loads the changed code and log why. Step 3b measures coverage over those tests only, reports it as partial and never asks or blocks on the threshold. The step 10 convergence re-run and every fix round use that command with `--scope scoped --if-stale`. The terminus prints `FULL SUITE — deferred-ci` (🟡) plus a `FULL SUITE — CI contract` line when the newest run of every local test command is green on the current tree, and refuses a red, stale or missing local run; carry both lines into the report and say the full suite runs in CI once a pull request is opened or updated.
