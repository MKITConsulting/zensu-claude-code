# TDD Plan: E2E-Tests für `zensu-plm` Agent

## Context

Spec (verbatim from user):

> Im Repo existieren E2E/Eval-Harnesses für `code-reviewer` und `tdd-manager`
> (`tests/e2e/`, `evals/tdd-manager`, `evals/tdd-review-chain`, `evals/config-gate`,
> `evals/plan-approval-hook`). Der `zensu-plm` Agent — zentraler Orchestrator für
> alle Zensu-MCP-Tools — hat keinen eigenen E2E-Test. Damit kann eine Änderung an
> `agents/zensu-plm.md` (Decision Rules, Tool-Listen, Workflow-Patterns) unbemerkt
> brechen.
>
> Ziel: Lokale Regression-Smoke einrichten, die sicherstellt, dass `zensu-plm`
> für definierte Prompts den richtigen Workflow wählt, die richtigen
> MCP-Tools nennt/aufruft und die Important-Rules befolgt.
>
> Default-Modus: Behavioral-Contract-Test ohne lebenden Zensu-MCP-Server.
> Pattern-Match gegen Text-Output von `claude --print --agent zensu:zensu-plm`.
>
> Spiegelung des `tests/e2e/` Harnesses. Niedrigste Komplexität, gleiche
> Konventionen wie bestehende Suite.
>
> Runner-Erweiterung (NEU gegenüber tests/e2e/run.sh): `match_pattern` muss
> Negativ-Asserts unterstützen. Lines die mit `!` beginnen, sind Negativ-Matches
> (müssen FEHLEN).

**Approach**: Strict Red/Green TDD. Test the harness logic (run.sh, setup-fixtures.sh) via plain-bash assertions — same style as `tests/e2e/test-runner.sh`. NOT testing live `claude --print` calls (manual smoke).

**Tech Stack**: bash 3+, git 2.28+, no npm/typescript dependency (zensu-plm fixtures are not buildable codebases — they are minimal git repos used as `claude --print` working dirs)

**Coverage**: SKIPPED — no coverage tool for bash scripts in this repo. Existing `tests/e2e/test-runner.sh` does not use coverage either.
